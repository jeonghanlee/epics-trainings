# 4.3 Connect three devices to one IOC

Use one reusable `iocshLoad` fragment to configure three independent
TCP connections. Each device needs a unique PV name, asyn port, and TCP port.

Complete [Create a reusable configuration](04.01.iocsh_basics.md) and
[Run the advanced simulator](04.02.iocsimulator2.md) first.

## Configure the three connections

The example uses these names:

| PV prefix | Asyn port | TCP port |
| --- | --- | --- |
| `MYDEMO:SIM1:` | `TCP1` | 9399 |
| `MYDEMO:SIM2:` | `TCP2` | 9400 |
| `MYDEMO:SIM3:` | `TCP3` | 9401 |

In `iocBoot/iocB46_182-jeonglee_Demo/`, save this as `st3.cmd`:

```
#!../../bin/linux-x86_64/jeonglee_Demo
on error break
< envPaths

epicsEnvSet("DB_TOP", "$(TOP)/db")
epicsEnvSet("DATABASE_TOP", "$(DB_TOP)")
epicsEnvSet("STREAM_PROTOCOL_PATH", "$(DB_TOP)")
epicsEnvSet("PREFIX", "MYDEMO:")
dbLoadDatabase("$(TOP)/dbd/jeonglee_Demo.dbd")
jeonglee_Demo_registerRecordDeviceDriver(pdbbase)

iocshLoad("$(TOP)/iocsh/training_device.iocsh", "DEVICE=SIM1:,PORT_NAME=TCP1,PORT=9399")
iocshLoad("$(TOP)/iocsh/training_device.iocsh", "DEVICE=SIM2:,PORT_NAME=TCP2,PORT=9400")
iocshLoad("$(TOP)/iocsh/training_device.iocsh", "DEVICE=SIM3:,PORT_NAME=TCP3,PORT=9401,ASYNTRACE=")
iocInit()
dbl
```

The fragment reads `PREFIX` and `DATABASE_TOP` from the IOC environment.
Each `iocshLoad` call supplies its device-specific values.
`ASYNTRACE=` enables tracing for the third connection.

Make the startup executable:

```bash
chmod +x st3.cmd
```

## Run and test all three devices

1. In three simulator terminals, start the advanced handler on each port:

   ```bash
   ./tcpserver.bash 9399 advanced_connection_handler.sh
   ```

   ```bash
   ./tcpserver.bash 9400 advanced_connection_handler.sh
   ```

   ```bash
   ./tcpserver.bash 9401 advanced_connection_handler.sh
   ```

2. In the IOC boot directory, start the IOC:

   ```bash
   ./st3.cmd
   ```

3. In an activated client terminal, request each handler's identity:

   ```bash
   caput -c MYDEMO:SIM1:Cmd "GetID?"
   caput -c MYDEMO:SIM2:Cmd "GetID?"
   caput -c MYDEMO:SIM3:Cmd "GetID?"
   caget MYDEMO:SIM1:Cmd-RB MYDEMO:SIM2:Cmd-RB MYDEMO:SIM3:Cmd-RB
   ```

   The replies must be three distinct numeric process IDs. `caput -c`
   waits for each asynchronous command to finish before the next command
   runs.

4. Request temperatures:

   ```bash
   caput -c MYDEMO:SIM1:Cmd "GetTemp?"
   caput -c MYDEMO:SIM2:Cmd "GetTemp?"
   caput -c MYDEMO:SIM3:Cmd "GetTemp?"
   caget MYDEMO:SIM1:Cmd-RB MYDEMO:SIM2:Cmd-RB MYDEMO:SIM3:Cmd-RB
   ```

   Each reply must be an integer between 0 and 100.

## Verification

Enter `dbl` in the IOC console. All six records, `Cmd` and `Cmd-RB`
for each device, must be present. Tracing for `TCP3` must appear when
you send its commands.

Comment out one `iocshLoad` line and restart the IOC. That device's
records must be absent while the other devices continue to work.
Restore the line, restart, and confirm that all three devices respond.

Enter `exit` in the IOC terminal and stop each simulator with Ctrl+C.
