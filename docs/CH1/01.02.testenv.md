# 1.2 Run your first IOC

Create one process variable (PV), run an Input/Output Controller (IOC),
and read and write the same value through Channel Access (CA) and
pvAccess (PVA).

1. In two Bash terminals, activate the matching installation from
   [lesson 1.1](01.01.installation.md). Set `TREE` in each terminal to that
   installation's absolute path, then direct clients to this host:

   ```bash
   source "$TREE/setEpicsEnv.bash"
   export EPICS_CA_AUTO_ADDR_LIST=NO EPICS_CA_ADDR_LIST=127.0.0.1
   export EPICS_PVA_AUTO_ADDR_LIST=NO EPICS_PVA_ADDR_LIST=127.0.0.1
   ```

2. In terminal 1, create a workspace outside the distribution:

   ```bash
   mkdir -p ~/ioc-training/first
   cd ~/ioc-training/first
   ```

   Save this database as `water.db`:

   ```text
   record(ao, "temperature:water")
   {
       field(DESC, "Water temperature setpoint")
       field(EGU, "degC")
       field(VAL, "0")
   }
   ```

   This analog output (`ao`) record has no hardware connection. A write
   changes its stored value; `EGU` identifies its engineering units.

3. Start the installed PVXS executable in terminal 1:

   ```bash
   softIocPVX -d water.db
   ```

   Wait for `iocRun: All initialization complete`. At the IOC prompt,
   list the records:

   ```text
   dbl
   ```

   The list contains `temperature:water`. Leave the IOC running.

4. In terminal 2, read the value and description:

   ```bash
   caget -t temperature:water
   caget -t temperature:water.DESC
   pvxget temperature:water
   ```

   CA returns `0` and `Water temperature setpoint`. PVA displays a typed
   structure containing `value`, rather than a JSON object.

5. Write through CA, then read through both protocols:

   ```bash
   caput temperature:water 24
   caget -t temperature:water
   pvxget temperature:water
   ```

   Both reads report `24`.

6. Write through PVA and read through CA:

   ```bash
   pvxput temperature:water 44
   caget -t temperature:water
   ```

   CA returns `44`: both protocols reach the same record.

7. In terminal 1, stop the IOC:

   ```text
   exit
   ```

## Exercise: Add an air temperature

Add a second `ao` record to `water.db`, named `temperature:air`, with
`DESC` set to `Air temperature setpoint`, `EGU` to `degC`, and `VAL` to
`20`. Restart the IOC and read both records:

```bash
caget temperature:water temperature:air
```

The restarted records begin at `0` and `20`. Client writes in this lesson
are not saved to the database file.

To observe a failed search without changing the host firewall, direct
the CA client to an unused local UDP port in terminal 2:

```bash
export EPICS_CA_ADDR_LIST=127.0.0.1:59999
caget -w 1 temperature:water
```

With no IOC search listener on that port, the read times out. Restore
the address and verify that the read succeeds:

```bash
export EPICS_CA_ADDR_LIST=127.0.0.1
caget -t temperature:water
```

An empty address list does not reliably cause failure when automatic
broadcast discovery is enabled. Keep it disabled for these local exercises.
