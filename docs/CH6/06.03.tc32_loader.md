# 6.3 Read 32 temperature channels

Run the Chapter 4 32-channel temperature database through `iocsh.bash` without
the compiled `jeonglee_Demo` executable, and group representative channels into
one structured pvAccess (PVA) object with `dbLoadGroup`. You inspect both
individual Channel Access (CA) and PVA records and a composite `QSRV2` group
process variable (PV) served by the Input/Output Controller (IOC).

## Prerequisites

* Complete [Run a 32-channel temperature simulator](../CH4/04.04.iocsimulator3.md)
  and [Generate and load 32 channel records](../CH4/04.05.db_templates.md).
* Confirm that `db/TC-32.db` and `db/tc32.proto` exist in `jeonglee_Demo/` with
  `$(P)$(R)` macros intact after the Chapter 4 exercises.
* Stop any IOC or simulator listening on port `9399`.
* Activate the matching EPICS-env 1.5.0 tree in the IOC and client terminals.

Open three Bash terminals on the same host with these roles and settings:

| Terminal | Role | Working directory | Environment |
| --- | --- | --- | --- |
| Terminal 1 | TC-32 emulator (`9399`) | `jeonglee_Demo/simulator/` | No EPICS environment required |
| Terminal 2 | IOC (`iocsh.bash`) | `jeonglee_Demo/` then `jeonglee_Demo/loader_tc32/` | `source "$TREE/setEpicsEnv.bash"` |
| Terminal 3 | CA and PVA client | Any directory | `source "$TREE/setEpicsEnv.bash"`, `export EPICS_CA_AUTO_ADDR_LIST=NO EPICS_CA_ADDR_LIST=127.0.0.1`, `export EPICS_PVA_AUTO_ADDR_LIST=NO EPICS_PVA_ADDR_LIST=127.0.0.1` |

In each EPICS terminal, set `TREE` to your installation path from
[lesson 1.1](../CH1/01.01.installation.md) (such as
`"$HOME/epics/1.5.0/debian-13/7.0.10"`) before running
`source "$TREE/setEpicsEnv.bash"`.

## Prepare the database, group JSON, and startup

1. In terminal 2 from your `jeonglee_Demo/` application directory, copy the
   generated database and protocol into a loader directory:

   ```bash
   mkdir -p loader_tc32
   cp db/TC-32.db db/tc32.proto loader_tc32/
   cd loader_tc32
   ```

2. In terminal 2 inside `loader_tc32/`, save this `QSRV2` group definition as
   `tc32_group.json`:

   ```json
   {
       "$(P)$(R)Summary": {
           "+id": "training:nt/TC32Summary:1.0",

           "device.model": {"+type": "const",  "+const": "TC-32"},

           "ch01":         {"+type": "scalar", "+channel": "$(P)$(R)CH01.VAL"},
           "ch16":         {"+type": "scalar", "+channel": "$(P)$(R)CH16.VAL"},
           "ch32":         {"+type": "scalar", "+channel": "$(P)$(R)CH32.VAL", "+trigger": "*"}
       }
   }
   ```

   Each mapping key configures how `QSRV2` assembles `LOADER:TC32:Summary`:

   * `"+id"` assigns the top-level PVA structure identifier
     `training:nt/TC32Summary:1.0`.
   * `"+type": "const"` with `"+const": "TC-32"` publishes a constant
     `device.model` string field without an underlying EPICS record.
   * `"+type": "scalar"` embeds each selected channel's `NTScalar` value, alarm,
     timestamp, and display metadata from `$(P)$(R)CH*.VAL`.
   * `"+trigger": "*"` on `ch32` publishes an atomic subscription update across
     all group fields when channel 32 finishes a streaming sweep. Omitting
     `+putorder` keeps the group read-only.

3. In terminal 2 inside `loader_tc32/`, save this startup file as `st.cmd`:

   ```
   on error break
   module StreamDevice

   epicsEnvSet("STREAM_PROTOCOL_PATH", ".")
   drvAsynIPPortConfigure("TC32", "127.0.0.1:9399", 0, 0, 0)
   asynOctetSetInputEos("TC32", 0, "\n")
   asynOctetSetOutputEos("TC32", 0, "\n")
   dbLoadRecords("TC-32.db", "P=LOADER:,R=TC32:,PORT=TC32")
   dbLoadGroup("tc32_group.json", "P=LOADER:,R=TC32:")
   iocInit()
   ```

   `softIocPVX` links `pvxs` with `QSRV2` enabled by default, so `dbLoadGroup`
   needs no extra `module` directive in `st.cmd`.

4. In terminal 2 inside `loader_tc32/`, preview the generated startup before
   launching the IOC:

   ```bash
   iocsh.bash -n st.cmd
   ```

## Read scalar channels and the structured group

1. In terminal 1 inside `jeonglee_Demo/simulator/`, start the TC-32 emulator on
   port `9399`:

   ```bash
   ./tc32_emulator.bash --port 9399
   ```

2. In terminal 2 inside `loader_tc32/`, start the IOC:

   ```bash
   iocsh.bash st.cmd
   ```

3. At the `iocsh` prompt in terminal 2, list the registered `QSRV2` group
   definition:

   ```
   pvxgl(1, "*")
   ```

   `pvxgl` reports the group name, atomic delivery mode, and four mapped
   members (`device.model`, `ch01`, `ch16`, and `ch32`):

   ```
   LOADER:TC32:Summary
     Atomic Get/Put:yes Atomic Members:4
   ```

4. In terminal 3, direct CA and PVA searches to loopback:

   ```bash
   export EPICS_CA_AUTO_ADDR_LIST=NO EPICS_CA_ADDR_LIST=127.0.0.1
   export EPICS_PVA_AUTO_ADDR_LIST=NO EPICS_PVA_ADDR_LIST=127.0.0.1
   ```

5. In terminal 3, read three scalar temperature channels and channel 01
   metadata through CA:

   ```bash
   caget LOADER:TC32:CH01 LOADER:TC32:CH16 LOADER:TC32:CH32
   caget LOADER:TC32:CH01.EGU LOADER:TC32:CH01.DESC LOADER:TC32:CH01.SEVR
   ```

   Live temperatures fall between `10` and `90` degrees `Celsius` with
   `NO_ALARM` severity:

   ```
   LOADER:TC32:CH01               77.1052
   LOADER:TC32:CH16               86.3493
   LOADER:TC32:CH32               76.6859
   LOADER:TC32:CH01.EGU           Celsius
   LOADER:TC32:CH01.DESC          TC temperature at Channel 01
   LOADER:TC32:CH01.SEVR          NO_ALARM
   ```

6. In terminal 3, read channel 01 as an individual PVA `NTScalar` record:

   ```bash
   pvxget LOADER:TC32:CH01
   ```

   same `ai` record:

## Verification

1. In terminal 3, read all 32 scalar channels once to confirm every record
   receives live stream updates between `10` and `90`:

   ```bash
   for ch in {01..32}; do caget -t "LOADER:TC32:CH$ch"; done
   ```

2. In terminal 3, inspect the published PVA type identifier on
   `LOADER:TC32:Summary`:

   ```bash
   pvxinfo LOADER:TC32:Summary | head -n 3
   ```

   The structure header shows the custom `+id` contract:

   ```
   LOADER:TC32:Summary from 127.0.0.1:43259
   struct "training:nt/TC32Summary:1.0" {
       struct {
   ```

3. In terminal 3, subscribe to three scalar channels with `camonitor` to verify
   continuous updates:

   ```bash
   camonitor LOADER:TC32:CH01 LOADER:TC32:CH16 LOADER:TC32:CH32
   ```

   Stop `camonitor` in terminal 3 with Ctrl+C, stop `tc32_emulator.bash` in
   terminal 1 with Ctrl+C, and then enter `exit` in terminal 2.
