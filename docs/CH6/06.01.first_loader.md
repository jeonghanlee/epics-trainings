# 6.1 Run an IOC with installed modules

Create a process variable (PV) using the installed `busy` module, start it
with the EPICS-env 1.5.0 loader, and change its value through Channel Access
(CA). Read the same value through pvAccess (PVA).

The `iocsh.bash` loader starts the installed `softIocPVX`, resolves the modules
named in your startup file, loads their recorded dependencies, and registers
their support. This exercise needs no IOC compilation or hardware.

## Prerequisites

* Complete [Install the EPICS environment](../CH1/01.01.installation.md).
* Use two Bash terminals on the same host, with `readelf` available
  (`binutils` provides it).
* Use a test host without another IOC publishing `TRAINING:Run`.

## Prepare the database and startup

1. In both terminals, activate the tree matching your operating system and
   direct the clients to the local host:

   ```bash
   HOST_ID="$(. /etc/os-release && printf '%s-%s' "$ID" "$VERSION_ID")"
   TREE="$HOME/epics/1.5.0/$HOST_ID/7.0.10"
   source "$TREE/setEpicsEnv.bash"
   export EPICS_CA_AUTO_ADDR_LIST=NO EPICS_CA_ADDR_LIST=127.0.0.1
   export EPICS_PVA_AUTO_ADDR_LIST=NO EPICS_PVA_ADDR_LIST=127.0.0.1
   ```

   If you installed the distribution elsewhere, adjust `TREE` in both
   terminals.

2. In terminal 1, create a workspace outside the distribution:

   ```bash
   IOC_WORK="$(mktemp -d)"
   cd "$IOC_WORK"
   pwd
   ```

   Keep this terminal in the workspace. Relative database paths are resolved
   from the working directory, even when the startup filename is absolute.

3. In that workspace, save this database as `busy.db`:

   ```text
   record(busy, "$(P)Run")
   {
       field(DESC, "Training loader demonstration")
       field(ZNAM, "Idle")
       field(ONAM, "Busy")
   }
   ```

4. Save this startup as `st.cmd` alongside `busy.db`:

   ```text
   on error break
   module busy
   dbLoadRecords("busy.db", "P=TRAINING:")
   iocInit()
   ```

   `module busy` selects the installed default version. The loader loads its
   dependencies before the database and calls support registration once.
   Your startup supplies the database instances and calls `iocInit()` once.

5. In terminal 1, preview the generated startup:

   ```bash
   iocsh.bash -n st.cmd
   ```

   The preview identifies `busy` and its dependencies, their library and
   database definition (DBD) paths, and
   `registerAllRecordDeviceDrivers(pdbbase)`. Resolve any reported error
   before starting the IOC. Preview mode does not initialize the database
   or prove that the running IOC works.

   The generated text uses `/dev/fd/3` and `/dev/fd/4` for files opened by
   that invocation. Keep `st.cmd` as your runnable file.

## Start the IOC and read its PV

1. In terminal 1, start the IOC from the workspace:

   ```bash
   iocsh.bash st.cmd
   ```

   Wait for `iocRun: All initialization complete` and leave it running.

2. In terminal 2, read the initial state through CA:

   ```bash
   caget -t TRAINING:Run
   ```

   The result is:

   ```text
   Idle
   ```

3. In terminal 2, set the busy state and read it through both protocols:

   ```bash
   caput TRAINING:Run 1
   caget -t TRAINING:Run
   pvxget TRAINING:Run
   ```

   The CA read prints `Busy`. The PVA response contains an enum value with
   index `1` and the choices `Idle` and `Busy`.

4. In terminal 2, restore the idle state:

   ```bash
   caput TRAINING:Run 0
   caget -t TRAINING:Run
   ```

   The CA read prints `Idle`.

5. In terminal 1, enter `exit` at the IOC prompt to stop the IOC.

## Module versions and startup files

To inspect the installed default, run this in an activated terminal:

```bash
readlink -f "$EPICS_MODULES/busy"
```

For the public 1.5.0 distribution, the directory ends in `busy-a4a272d`.
To select that version explicitly, replace the directive in `st.cmd` with:

```text
module busy a4a272d
```

Re-run the preview after a change. A missing module, incompatible requested
versions, or invalid metadata prevents startup. Dependency versions come
from the selected module's metadata.

Put `module` directives in the startup file passed to `iocsh.bash`. They
are loader directives; entering them at the IOC prompt or placing them in
an `iocshLoad` fragment does not load a module.

To preview from a shell without an activated EPICS environment, select the
tree inside the loader process. From the directory containing `st.cmd`, use:

```bash
"$TREE/base/bin/linux-x86_64/iocsh.bash" -e "$TREE" -n st.cmd
```

Set `TREE` to the absolute installation path first. The `-e` option activates
the loader process; it does not set up the calling shell for CA/PVA clients.

Chapters 2 through 5 teach IOC application builds and reusable configuration
files. Their compiled executables provide support through their application
DBD and registration function. Keep that startup sequence when following
those lessons; use this lesson's startup with `iocsh.bash`.

## Verification

The exercise succeeds when the IOC initializes, CA reads `Idle`, `Busy`,
and `Idle` in that order, PVA reports the busy state, and `exit` returns
terminal 1 to the shell. Keep `busy.db` and `st.cmd` in the workspace for
another run.
