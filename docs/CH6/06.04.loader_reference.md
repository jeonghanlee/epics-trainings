# 6.4 Module selection and loader errors

Use the loader options to inspect a startup and select the installed
module versions it requires.

## Loader command options

| Command | Result |
| --- | --- |
| `iocsh.bash st.cmd` | Start an interactive IOC |
| `iocsh.bash -n st.cmd` | Show the generated startup without starting the IOC |
| `iocsh.bash -S st.cmd` | Start without an interactive console |
| `iocsh.bash -e "$TREE" st.cmd` | Activate that tree inside the loader process |
| `iocsh.bash -h` | Show usage |

In these examples, run from the directory containing the startup and its
relative database files. Set `TREE` to the absolute installation directory.
The `-e` option does not activate the calling shell for client commands.

## Module directives

Put directives in the top-level file passed to `iocsh.bash`:

```text
module StreamDevice
```

This selects the installed default link. To require its 1.5.0 distribution
version, use:

```text
module StreamDevice 2.8.26
```

The function-style form is also accepted:

```text
module("StreamDevice", "2.8.26")
```

The names `mod` and `m` are aliases for `module`.
Directives placed inside an `iocshLoad` fragment or entered at the IOC
prompt do not select modules.

## Installed module metadata

In an activated terminal, inspect the default directory and its metadata:

```bash
readlink -f "$EPICS_MODULES/StreamDevice"
cat "$EPICS_MODULES/StreamDevice/cfg/iocsh.conf"
```

The metadata names the version, Base, architecture, libraries, DBD files,
environment macro, and exact dependency versions.
The loader resolves those dependencies before loading the requested module.
Use the installed metadata to determine versions rather than guessing from
a source checkout.

## Startup errors to recognize

| Error condition | Action |
| --- | --- |
| Module or exact version is absent | Select a version installed in this tree |
| Requested dependency versions conflict | Use one compatible set of module versions |
| Module metadata is missing or changed | Use a correctly installed distribution |
| A selected library cannot be resolved | Check the selected tree and runtime packages |
| Database or protocol path is wrong | Start in the documented workspace and correct the path |

A successful preview establishes module selection. Run the IOC and read its
PVs to verify database parsing, initialization, and device communication.
Keep the original startup file; preview output contains invocation-specific
`/dev/fd/` paths and is not a saved runnable IOC.

## Check a rejected module

In a workspace outside the distribution, save this as `st_bad.cmd`:

```text
module missing_training_module
iocInit()
```

Inspect it with the loader:

```bash
iocsh.bash -n st_bad.cmd
```

The loader must report the missing module and return a nonzero status.
Correct the directive before starting the IOC.
